# スクリプトを移植する

アプリには変換機能を入れない（利用者の決定）。移植は Claude がこの手順で行う。

## 置き方（移す先）

作業フォルダー（`get_web_url` の画面の 設定 → フォルダー、既定は `ドキュメント\PokeController`）の `スクリプト`:

```
スクリプト\
  <ゲーム>\              BDSP、SV、FRLG など
    画像\                そのゲームの 2 本以上で使う画像
    <分類>\              任意（例: 固定シンボル）。数が多いときだけ
      <スクリプト名>\     日本語でよい（例: エンテイ）
        <スクリプト名>.py
        画像\            この 1 本だけが使う画像
        （回数・設定などスクリプトが書くファイル）
  共通\
    画像\                ゲームをまたいで使う画像
    *.py                 複数のスクリプトで使う関数（from スクリプト.共通 import 名前）
  その他\                ゲームに属さないもの（動作確認など）
```

画像は名前だけ（`isContainTemplate('yuke.png')`）で、スクリプトの `画像` → 上のフォルダーの `画像` → `共通\画像` → `Template` の順に探される。一覧はスクリプトのフォルダーの 1 つ上でまとまる。

## 手順

1. **読むだけで調べる**: 渡された場所の下にある `SerialController\Commands\PythonCommands` と `SerialController\Template` を全部探す（コピーが複数あることが多い）。元のフォルダーは**書き換えない**。
2. **自作のものだけ選ぶ**: 本体付属のサンプル（`Samples`、`sample`、`ImageProcessingOnly`、`RankGlitch`、`bridge_functions` など。今のアプリに同梱済み）は移さない。迷うものは一覧にして利用者に聞く。配布 ZIP は中身を見て、まだ展開されていないスクリプトだけ移す。
3. **複数のコピーを比べる**: 同じパスのファイルを中身（ハッシュ）で比べ、違うものは差分を見て選ぶ。
   - スクリプト: 調整が進んでいる方（待ち時間・しきい値を詰めた方、壊れた行のない方）。判断がつかなければ両方の差分を利用者に見せる。
   - 「- コピー」などの複製、内容が同じで名前違いのものは移さない。
   - 回数などの記録ファイル（`.count` など）: 中の日付が新しい方（新しい厳選を始めた方）。
   - 画像: 同じ名前で中身が違うときは、それを使うスクリプトと一緒にあった方。別々のスクリプトが別の版を使うなら、それぞれの `画像` に置く（自分の `画像` が先に探される）。
4. **画像を振り分ける**: 各スクリプトのコードから画像の名前（`'….png'`、f 文字列のフォルダー名を含む）を拾い、1 本だけが使うものはそのスクリプトの `画像`、同じゲームの 2 本以上が使うものは `<ゲーム>\画像`、ゲームをまたぐものは `共通\画像` に置く。どのスクリプトも使わない画像は、関係するゲームの `画像\未使用` に置いて報告する（消さない）。コードが `'BDSP_Nazo/x.png'` のようにサブフォルダー付きで書いていれば、`画像` の中に同じサブフォルダーを作るか、コードの方をファイル名だけに直す。
5. **コードを直す（必要なところだけ）**:
   - 作業フォルダー（cwd）を前提にしたファイル（`open('webhook.txt')`、`'counts'`、`'thresholds.txt'` など）は `Path(__file__).parent` を基準にして、スクリプトのフォルダーに入れる。元のファイルも一緒に移す。
   - `'./Template/…'` や `os.path.join(os.getcwd(), 'Template', …)`、`__file__` から `SerialController\Template` をたどるパスは、スクリプトの `画像` を指すように直す（`IMAGES = Path(__file__).parent / '画像'` など）。
   - 作業フォルダーのパスには日本語が入る（`ドキュメント`、`スクリプト`）。`cv2.imread` / `cv2.imwrite` は日本語のパスを開けないので、`cv2.imdecode(np.fromfile(p, np.uint8), …)` と `cv2.imencode('.png', img)[1].tofile(p)` に直す。`isContainTemplate`、`self.camera.saveCapture`（絶対パス）は日本語のパスでよい。
   - 撮った画像のパスを `os.path.join('Captures', …)` で作っているものは、`self.camera.capture_dir`（設定で保存先を変えるとそこを指す）を使う。
   - `NAME` は一覧に出る名前。`lol_2` のような作業用の印や番号を外して整えてよい（`.count` などがファイル名から作られる場合は、ファイル名を変えたら記録ファイルの名前も合わせる）。
   - 動きそのもの（待ち時間、押すボタン、しきい値）は変えない。直したい点があれば報告する。
6. **秘密の値を出さない**: `webhook.txt`、`line_token.ini`、`discord.yml` などの中身は表示しない・会話に貼らない。スクリプトが読むものだけファイルごと移す。アプリ全体の設定（`settings.ini` など）は移さない（今のアプリの設定画面で設定する）。
7. **確かめる**: 構文を `python -m py_compile` で確かめ、`list_script_files` で並びを見る。アプリに読み込ませる（`restart_switch`、または画面の ↻）と、`list_scripts` に全部が出て読み込みエラーがないことを確かめる。実機では動かさない（利用者が頼んだときだけ、1 本ずつ）。
8. **気をつけること（実際の移植で分かったこと）**:
   - 移す作業は、Python のスクリプト（ファイルに書いたもの）で行う。シェルのヒアドキュメントに Python を書くと `\\` が `\` になり、正規表現や `\` で終わる行が壊れることがある。
   - 別のポケモンの画像を使っているスクリプト（コピーして作ったときの直し忘れ）は、その画像が「2 本で共有」に見える。動きを変えないためにそのまま `<ゲーム>\画像` に置き、報告で指摘する。
   - どのスクリプトも使わない画像は `<ゲーム>\画像\未使用` にまとめる（名前で探すときには使われない）。
   - 配布 ZIP（`ダウンロードしたプログラム` など）に、展開されていない元のスクリプトが残っていることがある。共有の画像と中身が違う画像は、そのスクリプトの `画像` に置く（自分の `画像` が先に探されるので、ほかのスクリプトに影響しない）。
   - tkinter で自前の窓を出すスクリプトは、アプリの画面ではなくデスクトップに窓が出る。動きは変えずに報告する。
   - 移したら、全スクリプトについて「コードに書かれた画像の名前が、名前だけで見つかるか」を確かめる（`Paths.find_image(名前, モジュール名)` がファイルを指すか）。
9. **報告する**: 移したもの（スクリプト・画像・記録ファイルの数）、選んだ版とその理由、直したコード、移さなかったもの、見つけた不具合（別のポケモンの画像を使っている、など）を短くまとめる。
